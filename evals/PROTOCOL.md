# 盲测与评分规程

用于判断 Praxis 在**没见过的题**上的真实水平，同时避免两种常见偏差：自评分偏高（看不见自己的盲点），和针对评语改进后再评（只学会了那一处）。

## 原则

1. **用没见过的题**。优先选模型知识截止之后才公开的赛题；更早的题可用，但要在报告里标明可能见过。已作为案例公开的往年题只能证明流程走得通，不证明水平。
2. **先封存再做**。给被测版本打 tag（如 `eval-1`），评测期间不改插件；每道题只跑一次；失败也记录，不挑好的报。
3. **评分标准先定**。参考该赛事官方公布的评阅要点，冻结本项目自定的条目、适用条件、权重和诊断规则；先写好，再看结果，不事后调整。官方一般要求不等于官方数字量表，不能把本项目分数解释为奖项分数线。
4. **评委独立**。能找到的人类评委最好是没参与开发、参加过该类比赛的人；找不到时用评委模型辅助，但只作相对比较，不对应奖项。
5. **评委要先做实际行为试验**。作者以外角色盲评有独立答案的对照稿与注入错误稿，保存发现、漏检和误报；再混排强弱论文检验排序、换顺序检验稳定性，保留全部结果。文档要求或聚合器单元测试不能代替该试验。没有实际记录就标“未校准”。
6. **检验“学会了”而不是“改了这一处”**。看到评语改进后，再做一道同类的新题，看同类缺陷是否还在。

## 不需要评委的部分

| 做法 | 测什么 | 可信度 |
|---|---|---|
| `evals.planted`：已知答案的合成题（规划、排队、传染、指派、结构判断、热传导、马尔可夫链、矩阵博弈、库存） | 公共开发题上的计算回归，不是 Agent 能力或插件增益 | 按 [oracle 契约](ORACLES.md) 的独立程度与容差解释 |
| 机械可查项：格式规范、能否在干净环境复现、数字前后一致、引用可查 | 交付质量与诚实 | 高 |
| 独立数学审计：另一个 Agent 或人逐条推导命题、独立复现数字（见案例的 `verification.json`） | 理论与数值的正确性 | 高，但覆盖有限 |
| 校准过的模型评委 | 论文相对水平 | 中 |

## 可以对外说什么

- 能说：有实际证据的工具回归通过率与评分版本、独立审计修正的问题数；只有真实运行、接触范围与隔离得到核验，才能称 N 题盲测。混排位次须附实际输入输出、论文来源和评委独立程度，不把计划当成结果。
- 不能说：诊断分自动对应某个奖项、评委声明就是论文正确性认证，或一次合成试验已证明真实比赛水平。用户要求奖项档次时可转述评委有具体依据的估计，保留相邻范围及“未校准”；没有真实标签和独立留出验证，不报校准概率。

## 步骤

```bash
git tag eval-1            # 封存被测版本
uv run --locked python -m evals.planted new queue 101      # 公共开发题，只打印题面和数据；不是盲测
uv run --locked python -m evals.planted check queue 101 '{"mean_wait": ...}'   # 键名取自题目输出里的 report 字段
```

赛题类的评测：把题面交给 Agent，按 [Praxis 的完整流程](../SKILL.md) 做一次，保存全部产物和过程记录；评分由评委按预先写好的标准完成。结果与失败一并记入 [学习回路](../references/learning-loop.md)。

真实 Agent 对照先做一个小场景，复用现有记录结构。A 不加载 Praxis、B 加载完整插件；模型、宿主、通用 Python 环境、资料和预算一致，记录工具差异、实际用量及人工介入。整体插件对照不能单独证明技能文字有效。每臂保存题面、插件及代码实际哈希（dirty tree 不能只填 HEAD）、执行入口、可用工具、过程日志、最终产物及失败；缺一臂不汇报增益。

评分端与执行端必须隔离：答案、生成代码及参考论文不在被测进程可读文件系统／工具范围，网络不能绕回公开答案。目录换名或要求“不许读取”不算隔离。运行前实际测试越权读取是否失败，失败就标明非盲开发试验；公开往年题仍可能在模型预训练中见过。普通 CLI `new` 的答案隐藏不满足这个条件。

评委的说明、完整schema与校准做法见 [judging.md](judging.md)，聚合脚本为 `evals/aggregate.py`。

每次评审先列关键主张并记录支持、反驳或待核，再填写七维诊断条目。新记录使用 `schema_version:2`，缺项拒收。`met:null`需明确不适用理由及定位；证据不足写 `met:false, reviewed:false`并解释缺口，不能靠删条目或写NA提高分。根因建立issue id，相关条目共引；诊断分仍按各条目汇总，但错误数按根因分析，不另行累计惩罚。关键主张判定与诊断分并列展示，发现改变结论的反例后必须解释影响范围，不能只报高总分。

聚合器只验证输入结构、证据文本非空、issue引用和算术。它不会读取论文核查证据真伪，不会独立判断主张是否正确，也不会推断真实获奖档次。旧直接分数保留为legacy，未提供关键主张表时标 `not_assessed`，不自动补造复核。历史评审留存原始结果；改进量表后重新评审须另存版本、输入哈希与差异理由，不能静默回填旧档。

最小行为试验应在评分规则冻结后，由未参与作者推导的角色实际执行；仅给题目、待评稿和规则，不给旧评分、注入清单或作者辩护。事先保存可核验正确答案、注入位置、预期受影响主张和验收条件。至少观察关键错误检出、无错误对照的误报、NA与缺证的区分，以及“可读但主张错误”是否被识别。报告评委是否接触过同题、角色独立程度、模型版本、实际输入输出和所有失败；同一模型家族的多个角色仍可能共享盲点。此试验验证评分行为，不自动校准奖项。

## 难度分级与运行预算

封存试做耗时长、花额度，不常规重复；每次运行必须学到东西。

| 级别 | 例子 | 怎么跑 |
|---|---|---|
| L1 已知答案的小题 | `evals/planted.py` 的九类题、工具测试 | 自动，每次提交 |
| L2 经典标准题 | 国赛 1998 A 案例 | 重跑示例，发布前 |
| L3 真实竞赛，标准路线 | 国赛 2018 A、2020 B | 封存试做，两次发布之间至多一次 |
| L4 真实竞赛，开放物理或搜索，无数据 | 美赛 2024 B | 同上 |
| L5 研究型，没有答案可对，只有可独立核验的部分结论 | 比多米诺更难的组合或结构问题 | 只在改动针对研究模式时跑 |

多米诺案例是研究模式的演示，难度低，不能当作研究能力的证据。

规则：
1. 运行前写下要检验的假设和什么结果算“学到了”，否则不跑；
2. 只在有改动针对该级别时才跑，没有新改动不重复同一级别；某级别没有新失败，就升一级；
3. 运行后写三行：失败了什么、根因、最小修复和防复发的检查；没有失败也写“没学到新东西，下次升级”；
4. 同一道题不跑第二次来“刷高”；修复后用另一道同级的新题验证。
