# 常用数学方法与工具：什么时候用、怎么验证

这是 methods.md 中“模型与验证一起选择”的条件参考。先看任务触发条件，再选工具；每种方法写明适用条件、可用工具、必须做的检查和常见误用。工具在插件里以 `praxis-tools` MCP 工具提供，也可在 Python 中直接调用 `modeling/` 模块，或用 `python -m scripts.mcp_server --call 工具名 '参数JSON'` 命令行调用。工具只负责计算，不判断模型是否适合问题。

| 任务触发条件 | 方法与工具 | 必须的检查 | 常见误用 |
|---|---|---|---|
| 有目标和硬约束的分配、调度、选址 | 线性／整数规划：`solve_lp`（给对偶间隙证书）、`solve_milp`（给界与间隙） | 手工可行解先行；LP 看间隙，MILP 看 `proved_optimal` 与 `mip_gap`；约束量纲逐条核对 | 把整数解四舍五入；把求解成功当模型正确；大 M 取值过大造成数值问题 |
| 路径、流量、连通与最小代价 | 网络：`shortest_path`、`max_flow`（同时给最小割）、`minimum_spanning_tree`；一对一指派 `solve_assignment`；往返路线 `solve_tsp`（启发式，附 1-树下界与差距） | 最大流等于最小割容量；路径长度手算一遍；负权边先另行处理 | 无向／有向混用；容量与流量单位不一致。`solve_tsp` 给的是可行路线加下界，差距不为零就不称最优 |
| 多方案比较，指标可量化 | `ahp_weights`（一致性比 CR）、`entropy_weights`、`evaluate_alternatives`（TOPSIS 与权重扰动稳定性） | 先查支配关系；CR<0.1 只是筛查约定；权重变化下的排名是否翻转 | 熵权当“重要性”（它只反映离散程度）；用同一批数据既定权重又当证据；指标重复计入 |
| 预测未来数值 | `backtest_baselines`（朴素、季节朴素、漂移、线性趋势、Holt 的滚动起点比较）；`gm11_forecast`（短正序列） | 候选模型必须胜过最好的基线；最终留出段不参与选型；GM(1,1) 报 C、P 等级 | 在几个点上拟合就外推；用训练误差说明预测能力；GM(1,1) 用于有明显波动或季节的数据 |
| 传染、扩散、种群等随时间连续变化 | 常微分方程：`sir_simulate`、`sir_fit`（报可辨识性）；一般模型用 `scipy.integrate.solve_ivp` | 守恒量；终态与解析关系（SIR 终态规模 z=1−exp(−R0 z)）；只有感染数据时 β、γ 强相关要如实报告 | 只拟合早期数据后外推峰值；把拟合优度当机制证据 |
| 等待、服务、容量 | 排队：`queue_mmc`（M/M/c 闭式）；到达或服务不符合假设时用离散事件仿真 | 利用率<1；Little 公式 L=λW；仿真给重复次数与置信区间 | 对非泊松到达直接套 M/M/c |
| 参数或假设不确定，影响结论 | 范围分析与全局敏感性：`sobol_sensitivity`（算术表达式，独立均匀输入） | 已知效应的小例子；样本量收敛；区间随结论改变否 | 敏感性当因果；把选定的范围说成概率分布 |
| 回归、分类、聚类、降维 | statsmodels（含诊断）、scikit-learn（交叉验证）；先用可解释基线 | 分组／时间留出；预处理只用训练信息；残差与多重共线性 | 数据泄漏；用测试集调参；把关联写成因果 |
| 非线性优化、控制 | `scipy.optimize` 多起点；分段常数控制族；SQP | 报告是局部最优；与更宽的族比较；上界或下界给出差距 | 单起点结果当全局最优 |
| 推导与量纲检查 | SymPy 符号化简与单位检查 | 代入数值反验；量纲一致 | 软件化简出的式子不核对适用条件 |

这些是条件分支，不是必经清单。一个任务通常只用其中一两项；任何方法都先说明它回答哪项任务，再说明验证。

## Python 够用吗

数值计算、统计、优化、网络、符号推导、微分方程与出图，NumPy、SciPy、pandas、statsmodels、scikit-learn、networkx、SymPy 与 Matplotlib 覆盖了绝大多数建模任务，可以替代 MATLAB 与 R 的常规用法。只有出现具体缺口时才考虑别的工具：框图式动态仿真、专门的偏微分方程求解器、某些 R 独有的统计包，或商业求解器（Gurobi、Lingo）才能处理的超大规模整数规划。此时先写明缺口与用途，核验来源与许可，再在任务记录里保留输入、命令和输出；未经需要不安装大型工具。HiGHS 已能处理常见规模的 LP／MILP，路径与排班类问题规模更大时再核验 OR-Tools。
