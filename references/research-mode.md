# 研究模式：没有标准答案时怎样工作

题目没有答案可对、结论要靠自己建立证据时读。这类问题包括：研究型建模（答案不唯一）、开放问题（没人知道答案）、以及“有没有更好的办法”。目标不是硬凑一个答案，而是产出**可检验的东西**，并如实标注每一项的把握程度。

## 题目的四个层次（探索难度，不是用途路由）

| 层次 | 例子 | 怎样判断做得好 |
|---|---|---|
| 竞赛题 | 有官方标准解法的往年题 | 建模、算法、计算、验证、写作；与标准答案和优秀论文对照 |
| 难度更高的竞赛题 | 研究生赛、没有见过的陌生题、跨学科题 | 能否迁移到陌生结构；能否在没有现成模型时找到路线 |
| 研究型问题 | 答案不唯一，评价看思路、假设、数学结构、验证 | 路线质量、假设是否可检验、验证程度、是否承认局限 |
| 开放问题 | 没有已知答案 | 是否提出了新路线、发现新结构、得到可验证的中间结论、缩小问题范围、找到反例或新猜想 |

此表用于选择探索与证据方法，不能决定交付用途或量表。研究生竞赛仍按竞赛题意、对应赛事—赛项—届次与 [竞赛评审](../evals/contest-judging.md)；开放竞赛没有唯一答案也不自动成为原创研究。明确以研究成果交付的论文才按 [研究作品评审](../evals/research-judging.md) 六项定性标准，不填竞赛七维、奖项或百分制。

层次越往后，整体质量越不能只靠一个标准答案评价；具体命题、证明和计算仍须判断对错。评价要区分**证据类型、覆盖范围和研究增量**。

## 能交付什么

没有标准答案时，下面这些可以成为有价值的产出，前提是各自带证据，并回应本次研究目标；完成一项简单复现不自动代表深度目标已完成：

- **可验证的结论**：一个界、一个恒等式、一个算法保证、一个已证明的特例。
- **反例**：证明某个看似合理的命题不成立。
- **缩小范围**：证明答案必然落在某个区间、某个集合里。
- **归约**：证明这个问题等价于或不难于一个已知问题。
- **猜想**：由数据或小例子归纳出的规律，标明检验到多大规模。
- **改进**：对已知方法的可量化改进，附比较。
- **计算结果表**：由可复现的计算得到的数据，供后续人使用。

开工说明相对已知基线的具体缺口，区分初步复现、已核验的增量和尚未确认的原创性。优先追求能改变判断的界、归约、机制或算法保证；不是只选最容易算完的特例。计算用时、整个研究投入和论文篇幅分别记录，不能互相替代。有限计算如能支持一个覆盖无限对象的严格归约，应明确前提与余下对象；极小的未覆盖密度也不能读成零。

继续投入前检查是否有能获得新证据的具体行动。若已经证明当前路线存在结构障碍，单纯增加枚举规模不会消除它，应保留有效结果、解释障碍并按原预算停止或转向。难题暂未解不等于整条路线无价值；也不能凭“很有希望”突破预算。版式专业不等于研究达到顶尖水平，未经文献与质量评审不作这种认定。

## 研究论文的质量目标

默认按面向专业数学或相应应用领域研究者、可供严格同行审查的质量组织论文；用户以顶级期刊为目标时，研究深度不能在“专业排版、计算跑通”处止步。分别核查问题价值、文献定位、可明确陈述的贡献、证明完整性、计算可靠性与表达。复现案例可以展示方法，但不能靠扩充文字或重排版升级为原创投稿成果。原创性待确认时，下一研究行动应针对具体文献差距或数学缺口；期刊是否适合、贡献是否足够，另行判断。

目标为 SIAM 时，先根据主贡献选具体期刊。科学问题与数学分析共同推进，可取 `--detail siam-siap`；数值方法设计或分析取 `--detail siam-sinum`；科学计算的算法、性能或软件创新取 `--detail siam-sisc`。用[期刊定位与证据要求](siam-research.md)明确最近结果、当前贡献和待补证据，再决定是否值得按该刊准备投稿。

跨学科应用仍以数学建模为主干，但模型内正确性与现实主张分层判断。确定路线及审读时，按 [研究主张检查](../evals/research-judging.md#按研究主张补充检查) 选择解析、机制、描述、预测、因果或决策所需的证据，再补实际学科的测量和适用条件；不因学科名称强制改用某个算法、随机实验或量表。纯数学贡献不强求经验数据，条件演算也不自动成为现实预测。

选题先写下想知道的具体量或命题，以及最接近的既有结果在相同条件下已经能回答什么。如果新增主张依赖区分两种解释，先找两种都符合当前证据的构造，计算它们对目标量的预言。例如只观测两种非负来源之和，能够确定总量，但分别削减哪一种更有效，可能随两者的分配翻转。写出仍可确定的范围和能区分两者的观测，再决定下一步是收数、推导还是缩小主张。

引言说明已知什么、缺什么、本稿具体解决什么；定理保留全部前提，证明明确依赖，计算命题交代有限覆盖与独立检查。正文以数学内容为主，开发路线和验收日志放复现材料，具体结论依赖的条件就近说明。原创性状态、证据等级及与目标期刊的差距等评审结论记在评审记录和交付说明中，正文通过引用与明确的贡献陈述定位已有工作，不写成自我评价；摘要和结论陈述发现及适用条件，局限集中在专门一节并说明影响与补救方向。正式主报告命名按 [writing.md](writing.md#正式报告文件命名)。工作论文从主文语言选起稿方式。运行 `python -m scripts.paper_template report.tex --init-research zh` 新建中文研究稿，选 `en` 新建英文稿。中文采用 CTeX 的中文字号、段落、摘要、关键词及命题环境，英文采用 AMS 的标题、短页眉、摘要及证明环境。两稿共用数学论证和证据方法。以目标期刊或会议指定样式投稿时采用其类文件和文献格式；主办方未规定时按正文语言和读者选择工作论文模板。共享模板的成稿可用 `python -m scripts.paper_template report.tex --contest research` 核查；历史 AMS 稿仍按原样式验收。

图按论证需要选择：构造或反例图应帮助检查证明，计算图应揭示表格难以直接表达的结构。没有这种价值就不加；有必要的解释也不能因稿件较短而省略。图内区分离散点、连续曲线、插值和阶梯；图注的左右／上下指向须与实际渲染一致。将图、算例、数值表与摘要对应到有效证据，最终查看每页实际成品。页数、图数与期刊档次分别判断，不设置装饰图或凑篇幅指标。

## 实验数学的循环

1. **算小例子**：把问题的最小规模版本做成可穷举或可精确求解的程序，得到一批数据。
2. **猜规律**：对序列用 `guess_sequence`（线性递推与多项式，精确有理数；`holdout` 留出最后几项检验猜测，方程数远多于未知数才算有冗余）；对数值常数用 `find_relation`（PSLQ 整数关系）；对函数关系用 `probe_structure` 判断单调、凸、对称、幂律。
3. **检验猜想**：在更大规模或更高精度上检验：`test_conjecture`（等式或不等式，随机点）、`modeling.experiment.test_conjecture`（mpmath 高精度）。不要拿拟合所用的数据当检验数据。
4. **找反例**：`find_counterexample` 对整数域做穷举（总数不超过 `exhaustive_limit`，默认 20 万；在忠实的精确整数谓词下“无反例”才是对该域的证明，输出 `proved_for_domain`；实变量、浮点常量、真正除法及未认证的负／变量幂仅报告数值检查），更大的域只是抽样；穷举发现反例时 `cases` 记录已检查数、`exhaustive` 为真（表示采用穷举策略，并非已完成全域）。只有全部求值成功且无反例时才能给出域内证明；异常与非有限结果记录为 `evaluation_errors`，不算反例。命令行里只能写算术、比较和 `isprime`、`gcd` 等；要检验序列上的断言（如递推）用 `check_recurrence` 或自己写脚本。发现反例后，在 `shrink_budget`（默认 1000 次求值）内向简单形式缩小，再据此修改猜想；检查 `shrinking.status`，预算耗尽仍保留实际候选及其求值条件，不宣称全局最小。
5. **尝试证明**：给出证明草稿，标明哪些步骤已严格、哪些只是论证。能用交换论证、归纳、守恒、单调性、对偶的先试。
6. **记录**：对实验数学中的每个命题按下表记录证据状态，并保留失败的尝试和被排除的方向（`route_graph` 与 `lesson_add`）。

## 从已证结果到更强贡献

最近工作对照显示核心结论可由已知原理推出时，先回头分析已有证明，再决定是否需要新增算例或数据：

1. **找实际用到的前提**：逐步标出证明使用的性质（正性、线性、单调性、凸性、守恒、谱结构等）。未用到的前提就是可以放宽的方向；常数系数、连续在场、单一状态等常是计算方便的设定。
2. **找推动结论的结构**：把结论改写成某个算子、变换或序关系的性质。例如“排序至多翻转一次”可改写为“对非负权重积分不会增加变号次数”。这样一次证明可覆盖多种情形，也容易找到对应的经典工具。
3. **写最弱前提下的命题**：先让结论覆盖原有各个情形，再检查新命题能推出哪个原先没有的判断，例如新的上界、充分条件或可测判据。
4. **证明紧性并找失效边界**：给出达到上界的构造，并用精确值、区间算术或符号计算核定；再构造违反关键前提的反例，说明哪一条前提不能去掉。
5. **重做最近工作对照**：对推广后的命题重新检索，按[逐条判断](literature-review.md#逐条判断相对已有工作的贡献)代入先例，并补查研究同类推广对象的文献。工具已知、应用命题未见时，写作已知工具的新应用定理，不写作新的数学方法。
6. **写回应用含义**：说明推广如何改变测量或决策。例如上界只依赖源项时，可以先在受控装置中测源项，不必对每种场景逐一实测。

这一步能否产生贡献要看结果：没有找到更强命题、紧性构造或新判断时，如实保留原结论的定位，不靠改写措辞抬高贡献。

## 实验数学命题的证据状态

下表区分同一数学命题在探索中获得的不同证据。经验研究保留估计对象、识别前提及观测范围；同一篇稿件中，数学命题与经验主张可以各自成立到不同深度。

| 等级 | 含义 | 允许怎样表述 |
|---|---|---|
| 已观察 | 在若干例子中看到 | “在……例子中观察到” |
| 已猜想 | 归纳出规律但无检验 | “猜想”，不写成事实 |
| 已检验到规模 N | 区分全域穷举与随机抽样，记录覆盖范围、样本数和求值失败 | 只有全域穷举且每项精确核对成功时才写“在该有限域成立”；抽样只能写“已检查的样本中未发现反例”，不能推广到未覆盖范围 |
| 证明草稿 | 有论证思路，关键步骤仍待核对或补全 | “证明思路如下，尚未完全核对” |
| 已证明（有限核对） | 严格的框架加有限项的精确核对（见下） | “定理：由……阶数上界与前 N 项核对” |
| 已证明（完整） | 每一步都核对过，或有机器验证 | “定理” |
| 已推翻 | 找到反例 | 给出反例 |

有完整证明的数学命题可在论文中陈述为定理。关键步骤尚无论证时，陈述已证特例或明确提出猜想。独立推导、形式化验证及审读覆盖范围另记在核验记录中。数值上“检验到很大规模”也不是证明。

**线性递推的有限核对模板**（严格）：若已知序列满足某个阶数不超过 N 的常系数线性递推（例如它等于 uᵀMⁿv，M 为 N×N 矩阵，由 Cayley–Hamilton 得阶数不超过 N），候选递推的阶数为 d，设该递推为 P(E)a=0（E 为移位算子），候选递推为 Q(E)a，则差序列 b=Q(E)a 也满足 P(E)b=Q(E)P(E)a=0（多项式算子可交换），即 b 满足同一个阶数不超过 N 的首一递推；这样的序列只要前 N 项为零就恒为零。所以从头开始连续 N 条方程成立（数据里的 N+d 项）就是完整证明。`check_recurrence` 的 `order_bound` 参数给出所需方程数并判断是否已够。例：3×2n 多米诺铺法数用 8 个列状态的转移矩阵，N=8，候选 aₙ=4aₙ₋₁−aₙ₋₂，d=2，前 8 条方程（a(0) 到 a(9) 共 10 项）成立即为完整证明。这里的 N 本身要有依据（如转移矩阵的大小），否则只是证据。

## 与路线记录的对应

`route_graph` 的 `keep_result` 的 `status` 可以直接用阶梯的词：`observed`、`conjectured`、`checked_to_N`、`proved_sketch`、`proved_finite_check`、`proved`、`refuted`（也接受 `derived`、`checked` 等证据等级）。研究型问题通常用 `mode: "exploratory"`；备选路线若显然站不住，直接 `kill` 并写一行原因。

## 文献与新颖性

- 声称“新”之前先检索：用 `search_literature` 查标题和关键词，从实际可用的开放入口核读全文；`find_open_access` 的邮箱授权和替代入口按 [literature-review.md](literature-review.md)，不将它设为必经工具。记录检索词、日期与实际范围；检索不到只说明“本次未检到”，不能说“不存在”。
- 定位主要贡献时取 `--detail closest-work`，按[与最近工作的逐条对照](literature-review.md#逐条判断相对已有工作的贡献)尝试从应用模型和数学先例共同推出主张。记录代入后剩下的论证、反例针对的前提，以及会改变的实际判断。
- 引用时区分原文给出的结论、原文的数值证据、自己的推论。

## 诚实边界

- 只有完整命题已被证明、所有关键前提和覆盖范围均成立且经过独立核对，才能声称解决对应问题。局部定理、有限证书或验证器通过不能替代对一般命题的证明；机器检查还须核对其编码的命题是否就是所声称的命题。
- 不用“标准答案”的叙述方式写没有标准答案的结果。
- 失败也是结果：写明试过什么、卡在哪里、排除了哪些方向。
- 计算得到的常数、关系（PSLQ 等）只是线索。高精度独立计算可支持数值使用，但不能替代解析证明、精确反例或完整误差界；输出等级按 [数学工具结果契约](automation.md#数学工具的结果契约) 判断。

## 探索过程自查（不替代作品评审）

完整研究作品的质量评价归 [research-judging.md](../evals/research-judging.md)；下面只自查探索过程。没有标准答案时仍核查命题、证明与计算正确性、真实来源和实际成品，不因研究用途关闭这些检查：

- 是否提出了至少一个新的、可检验的路线或猜想？
- 每个结论的把握等级是否标注并与证据相符？
- 是否有反例搜索，找到的反例是否被用来修正猜想？
- 中间结果能否被他人复现（脚本、种子、数据）？
- 是否把已知结果误当新结果？
- 失败和被排除的方向是否留下记录？
