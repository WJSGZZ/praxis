# 路径搜索：产生、探索、攻击、淘汰、重组

模型选择不是“看到题就套模型”，而是在几条真正不同的路线之间做有记录的比较。问题陌生、第一条路线看起来太顺、或结论影响大时使用；标准题只需在任务记录里写一行“为什么选它、放弃了什么”。

## 一条路线是什么

路线 = 一种看待问题的方式 + 它依赖的结构与假设 + 需要的信息。**不同路线要在结构或表示上不同**（连续与离散、确定与随机、优化与仿真、解析与数值），不是同一模型的参数变体。

## 流程

1. **产生（至少三条）**：从结构发现（[structure-discovery.md](structure-discovery.md)）得到的结构各取一条，再加一条“最简基线”。列出每条的假设和所需信息。
2. **廉价探索**：对每条路线做最小的实验，不求答案，只求能不能活：手算一个小例子、取极端情形、写一个十行的原型。预算内完成，不在一条路线上深挖。
3. **攻击**：对每条存活的路线，用至少一种方法正面进攻它的最弱假设：
   - 逆向：什么情况下它会给出荒谬结果？结果反过来会怎样？
   - 事前验尸：假设这条路线一周后被推翻，最可能的原因是什么？
   - 证伪：什么观察会证明它错？去做那个检查。
   - 反例搜索：`find_counterexample`、`test_conjecture`，或构造小规模穷举。
   - 独立方法：换一种完全不同的算法得到同一个量，看是否一致。
   - 去掉一个假设：结果变多少？
4. **淘汰并留存**：路线被推翻，写明原因，并把**仍有用的中间结果**留下（一个界、一个恒等式、一个失败时暴露的结构），标注可复用到哪里。被淘汰的路线不是浪费。
5. **重组**：把存活路线的有用部分合成新路线：线性松弛给界，仿真给检验；解析解给初值，数值优化精修；简化模型给基线，复杂模型给修正。合并时写明怎样连接、单位与假设是否一致。
6. **收敛**：按下面的比较维度选出最终路线，写明理由、放弃了什么、哪个假设失效时转向哪条路。

## 两种记录粒度

- **`mode: "exploratory"`（默认）**：陌生或高影响的问题，选定前要有三条路线、一次存活的攻击、每个假设的后备。
- **`mode: "standard"`**：教材里有直接对应方法的题（单个线性规划、标准排队、均匀介质热传导、一次回归），只要基线加一条备选、一次存活的攻击，记录几行即可。一道题若只有一条自然路线，也用这个模式，不要为凑数编造稻草人路线。
- 多问题赛题每个子问题一张图（一张图只能选定一条路线）；`graph_file` 可以各用各的文件。
- 在命令行里用 `route_graph` 时给 `graph_file`（项目内的 JSON 路径）：存在就读入、操作后写回，不必每次把整张图作为参数传入。
- 明显站不住的备选（例如一个过于简单的基线）可以直接 `kill` 并写一行原因，不必为它编造攻击；攻击留给仍然活着的路线。

## 一个完整的最小例子

`route_graph` 的 `operations`（JSON）：

```json
[
 {"op": "add_structure", "key": "tu", "text": "约束矩阵是有向图关联矩阵", "evidence": "checked"},
 {"op": "add_assumption", "key": "integral", "text": "供给与容量为整数", "evidence": "assumed", "if_false": "改解整数规划"},
 {"op": "add_path", "key": "lp", "title": "最小费用流（线性规划）", "structure": "tu", "assumptions": ["integral"]},
 {"op": "add_path", "key": "milp", "title": "弧流量整数规划"},
 {"op": "add_path", "key": "greedy", "title": "按单位费用贪心"},
 {"op": "attack", "key": "lp", "claim": "线性规划顶点是整数", "method": "check_total_unimodularity", "outcome": "survived"},
 {"op": "kill", "key": "greedy", "reason": "无最优性保证；仅作基线"},
 {"op": "keep_result", "key": "bound", "statement": "线性规划松弛给出费用下界", "status": "derived", "source_path": "lp"},
 {"op": "choose", "key": "lp", "why": "整数最优且有对偶证书"}
]
```

字段名以 `--describe route_graph` 和 `modeling/routes.py` 的函数签名为准；`add_path` 的 `structure` 只能写已登记结构的 key。

## 比较维度

评分只用来迫使自己说出理由，不当作客观结论。每个维度 1–5，并在备注或攻击里给依据：

| 维度 | 问什么 |
|---|---|
| 假设（assumptions） | 依赖的假设多不多、强不强、有没有依据 |
| 信息（information） | 需要的数据和参数拿不拿得到 |
| 可处理性（tractability） | 能否在预算内求出可靠解 |
| 稳健性（robustness） | 假设略偏时结论变不变 |
| 可验证性（verifiability） | 有没有独立办法检验结果 |
| 解释力（explanatory_power） | 结果能否说明“为什么”，而不只是“是多少” |

## 记录：`route_graph` 工具

用 `route_graph`（或 Python 的 `modeling.routes`）保存整个搜索，格式是普通 JSON，放进任务记录：

- `add_structure`、`add_assumption`（带证据等级和“若不成立则怎么办”）、`add_path`；
- `attack`（被攻击的断言、方法、结果：survived / weakened / killed）；
- `kill`（必须写原因）、`keep_result`、`merge`、`choose`。

记录会拒绝：没有原因就淘汰、没有经过存活的攻击就选定、备选不足（默认模式下少于三条路线，`standard` 模式少于两条）就选定、假设没有“若不成立”的后备。`choose` 之后，工具返回一份可读的路线记录，可压缩成论文里“为什么这样建模”的一小节或附录。

## 预算与停止

- 时间由请求范围和剩余预算决定；限时任务按 solo-delivery 的优先级先保证完整稿。
- 探索有上限：每条路线的探索不超过总预算的一小部分；某条路线已经被一个简单检验推翻，就不再投入。
- 证据足够就停。不为“显得全面”而增加路线；不把全部工具设为必经步骤。
- 已经有成熟标准解法、风险低的题，路线记录压缩成一行；记录的详细程度与结论影响成正比。

## 常见失败

- 候选路线其实是同一模型的三种参数：重做，换结构。
- 只攻击自己不担心的假设：先攻击最弱的那个。
- 只记最终选择，不记淘汰原因：下次会重走同一条死路。
- 因为某条路线“看起来高级”而偏爱：写下它比最简基线多回答了什么，答不出就不选。
