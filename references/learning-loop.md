# 学习回路：每做完一题都变得更强一点

当任务暴露了可迁移的成功或失败时，把结构、识别信号、路线取舍与验证方法提炼成带条件的经验。任务记录保留本题的决定与证据；课程是可复用的提炼，不再建一套本题过程台账。

## 什么时候做

- 完整任务结束时简短判断是否有新经验；限时任务先完成必要验证与交付；
- 路线被推翻、模型被修正、或被用户纠正时，先修所属规则或工具及必要回归检查，再提炼经验；
- 没有新东西可学的任务不硬写。

## 复盘问什么

1. 这题的结构是什么？一开始认对了吗？什么时候才认出来？
2. 试过哪些路线？各自死在哪里（假设、数据、计算、验证）？
3. 起作用的变换或视角是什么（松弛、对偶、变量替换、分阶段、守恒……）？
4. 哪次检查发现了问题？有没有本该更早做的检查？
5. 哪条原则下次遇到类似问题可直接用？它在什么条件下才成立？
6. 哪些地方我其实不确定？用什么证据等级标注？

## 从多轮改进中提炼经验

长期打磨过的案例，先按实际版本追溯关键改动，不把最终稿倒填成最初就会的路线。只选会改变答案、可信度或读者理解的节点，链接原运行、失败、评议和成稿；复用已有记录，不为每轮建立新台账。

区分四类变化：**模型／决策**改变了什么答案；**验证**排除了什么错误或缩窄了什么范围；**表达**让哪些已有结论更容易理解；**评价**纠正了什么判据或检查范围。它们可以同时发生，但奖项估计变化不能独自证明某项改动的收益。版本比较及判据变化按 [评测约定](../evals/judging.md)，论文主线按 [writing.md](writing.md)；不从一次升档轨迹推导通用获奖步骤。

提炼时写清“什么信号触发行动—行动解决什么缺口—用什么证据接受或拒绝—什么条件下不能照用”。将规则合并到所属方法，案例证据留在本地课程。例如，参数仍有歧义时可检查推荐是否对相容解释都有效，而非一律再拟合更多参数；一次准备有成本时比较完整服务的总成本，而非只比后续运行量。具体计算与适用条件仍回到相应方法，不把这些例子设为全题必做项。

下一题在路线形成前检索相关课程，核对触发信号和条件；有实质缺口才调用。可用廉价异题解析例先反驳过宽原则，但它只检验该局部性质，不认证整题自主能力或奖项水平。完整任务中的实际使用及独立核验另存观察；未发生的迁移保持待验证。

## 记录：`lesson_add` 与 `lesson_search`

课程存成 JSON 行，放在**用户的项目里**（如 `planning/lessons.jsonl`），不上传、不共享。

- 必填：`problem`、`structure`、`recognized`、`routes_tried`、`what_failed`、`what_worked`、`verified_by`、`principle`；
- 可选：`tags`、`evidence`（candidate / observed once / seen repeatedly / derived / checked on a held-out problem）、`source_kind`（external_proposal / task_observation / mathematical_derivation；旧记录为legacy_unspecified）；
- `principle` 要写成能迁移的规则，不是对本题的描述。

路线记录完成后，`route_to_lesson` 可起草课程。逐项审核草稿是否忠实于真实尝试，再补写适用条件与可迁移原则，交给 `lesson_add`；自动起草不代表已经学会或验证。

已有课程且当前结构可能相关时，用 `lesson_search` 按关键词和标签检索；`route_graph` 新建图时传 `lessons_path` 也会返回相关经验。候选形成前审读，检索命中只是提示，不替代本题检验。

同一活动记录重复写入返回原ID，不产生一次新观察；不同任务或新证据仍可分别记录。修订课程时在完整新记录中给 `supersedes: ["L0001"]`，只替代当前活动ID。证据推翻但没有替代规则时，调用同一 `lesson_add`，传 `lesson: {"event":"retire","target":"L0001","reason":"具体证据与原因"}`。检索与结构计数使用去重后的活动视图；替代链、退役和原文都留在JSONL。不存在的引用、自引用和循环拒绝，不静默删除坏记录。`modeling.lessons.load`仍读取历史课程原文；既有workflow保存的检索ID、记录哈希和当时索引哈希不随当前库更新而改写。

外部材料的新建议先以 `source_kind: external_proposal, evidence: candidate` 入库；本题实践核验后另存带实际证据的 `task_observation` 或 `mathematical_derivation`，明确替代关系。元数据是来源声明，不是自动认证；检索排序、重复存入和同题重放不能将经验升级为异题验证。成熟且通用的规则合并到所属参考或工具，私有来源与案例细节留本地；本题专用结论不进入默认核心。没有适用的下一题时保留候选，不为晋升经验启动昂贵研究。

## 公共开发题与工具回归：`evals.planted`

改动工具或指南后，用已知答案的合成题检验没有退步：

```bash
uv run --locked python -m evals.planted list
uv run --locked python -m evals.planted new queue 7
uv run --locked python -m evals.planted check queue 7 '{"mean_wait": 0.42}'
```

题目由 (类型, 种子) 生成，题面不含答案；`new` 输出的 `report` 字段给出答案要用的键名（如 `{"r0": ..., "final_size": ...}`）；`check` 按种子重算真值并评分。公开生成器加新种子仍可重建答案，属于开发题或工具回归，不自动成为隔离的 Agent 盲测。真正盲测须按 [evals/PROTOCOL.md](../evals/PROTOCOL.md) 核验访问隔离、接触范围和实际运行；CLI 隐藏答案不足以满足隔离。

## 同题资料与接触范围

按用途区分开发／学习题、阶段验证题、少量最终保留题，沿用已有清单，不强制更名或固定比例。开发题可看参考并反复改进；阶段验证先固定自主成果再评估、学习；最终保留题在约定验收时才启用。此处训练通常指方法与工具开发，不自动表示模型权重训练。

**执行顺序：** 固定插件版本、允许输入、预算与评估重点 → 预算内自主研究、自检和修稿 → 保存首次完整稿及封存自主终稿（源码／环境／数据／产物版本与时间）→ 评估者先审固定稿，再读合法同题参考 → 学习修订另存 → 用另一题检验迁移。一次委托允许多轮改进；不要求初稿就停止。正式赛事另按当届规则处理。

执行端在封存前不访问同题答案、生成代码或参考论文；评估端在封存后可以读，反馈不得回填该次自主成果。严格测试按 [评测协议](../evals/PROTOCOL.md) 实测隔离；隔离不足如实标记。未知用途先保持参考隔离，继续不依赖答案的检查。通用文献、原始数据与允许资料不因“同一领域”自动禁读。

**无答案也要评估：** 数学／数据用解析特例、守恒、穷举、界、独立实现及泄漏检查；作品检查题意覆盖、条件与结论、全文协调和实际页面；对照参考评价路线与表达。获奖作品不自动成为真值，不按与其数字／方法一致程度判正确；无法确认的现实适用性或奖项水平写待核，不用内部高分填补。

**暴露按时间处理：** 封存前误读记录来源、题目、版本、实际范围并停止继续读取，保留已有成果，撤回不成立的未见／盲测主张；封存后按计划看参考不抹掉既有自主稿的证据，后续修改为学习版本。项目历史暴露、本次执行输入、封存后参考阅读分别记；预训练接触未知，删除文件、回滚或换Agent不能清零历史。仅看分数后反复针对同题调试也使它成为开发材料。

同题回归可验证具体修复、兼容与稳定性，不证明改进迁移到未见题。案例用途（旗舰／研究归档／开发回归／留出）和执行方式（自主／人机协作／开发者精修）分开记录；复用已有记录，最低包含用途、版本、封存时间、暴露、评估范围及结论，不新建平行台账。旗舰可维护；研究归档保留原版，重要错误附勘误与修订关联。

题库是否留出与单题内部预测数据的训练／验证／测试切分分别核验，不能互相替代。

## 成长的边界

- 记录要真实：失败写失败，不改写成“当时就认出来了”。
- 不因为一次成功就把原则写成“规律”；证据等级随复现次数提升。
- 课程也会过期：工具、规范、数据源变化后，旧课程要重新检验。
- 不把用户的私人信息、赛题原文或未公开材料写进课程。

教训可带 `failure_pattern`（失败做法）、`detected_by`（发现方法）、`signal`（下次留意的信号）；它们和其余字段一起被检索。一个经验只有迁移到未见问题并经相称检查后，才提高证据等级；重复存储或被检索到不算新的验证。
