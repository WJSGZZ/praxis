# Praxis 的统一建模方法

目标：在用户需要的范围内，回答原始问题，并让结论强度与证据相称。所有方法围绕同一份任务记录工作；来源不是流程分支，算法不是默认步骤。

## 工作单元与记录

工作单元是一个需要回答的问题，使用 Q1、Q2 等任务 ID。先从原文列出要求，再围绕每项定义、选择路线、实现、验证和表达结论。持续任务沿用项目已有记录；使用案例系统时，planning/tasks.md 是含义、取舍、假设与依赖的主记录，planning/requirements.json 只是数值任务的机器索引，使用相同 ID，不另建一套模型解释。成熟解法的小问题可直接回答，不为套流程新建记录。

任务处理顺序依据依赖与影响：先解决会改变其他答案的定义和数据，再实现依赖它们的模型。可独立推进的任务继续做，不因一个局部未知冻结全题。跨案例依赖需显式记在 tasks.md，当前工具不会自动传播它们。

## 一条主线，按请求范围进入和结束

| 环节 | 要解决的问题 | 使用的输入 | 形成的产出 | 何时推进 |
|---|---|---|---|---|
| 明确问题 | 什么答案才算回答了原题？ | 原文、目标、数据来源与可用信息边界 | 任务 ID、目标量、单位、约束、交付物与验收依据 | 会改变主要答案的歧义已解决，或按授权目标作条件分析 |
| 形成路线 | 问题背后是什么结构？用什么最小模型能回答它？ | 明确的问题、现实机制、数据能力 | 发现的结构、基线、必要假设、不同结构的候选及淘汰原因、验证设计 | 路线可实施且可验证；新增复杂度有实际用途 |
| 取得结果 | 如何按路线可靠地计算？ | 审核后的模型、数据处理与参数 | 模型代码、独立验证器、实际运行及结果 | 输出有效，运行与记录对应；失败定位后修复 |
| 判断证据 | 这些结果能支持多强的结论？ | 原问题、模型、有效运行和独立对照 | 正确性、适用范围、稳健性及剩余不确定性 | 证据支持拟表达结论；否则修复或降低结论强度 |
| 完成回答 | 怎样清楚地交付原题要求？ | 对应任务的结论、来源与有效证据 | 分析、建议、图表或报告，以及未解决事项 | 对照请求范围逐项交付，数字与结论一致 |

这些环节是推理关系，不是五次审批。“形成路线”按问题的陌生程度伸缩：标准题只写一行“为什么选它、放弃了什么”；陌生题先做[结构发现](structure-discovery.md)，再按[路径搜索](path-search.md)比较至少三条结构不同的路线并留下记录；没有标准答案的问题改用[研究模式](research-mode.md)；任务结束时按[学习回路](learning-loop.md)留下可迁移的经验。用户只要求分析时，完成问题与路线即可；审核已有模型时从其实际缺口进入；完整建模才走到结果与交付。写作结构服从实际交付规范，不要求每一段对应一个流程环节。

## 按缺口读取，规则各有归属

专项技能按用户请求进入主线，参考文件承担不同判断；不能把它们逐份读完再推进。

| 当前缺口 | 规则归属 | 读完形成什么 |
|---|---|---|
| 不清楚该调用哪项能力 | [capabilities.md](capabilities.md) | 当前主责与交接内容 |
| 不知道结构与候选路线 | [structure-discovery.md](structure-discovery.md)、[path-search.md](path-search.md) | 有依据的结构、候选与取舍 |
| 表示、识别能力或最优性不清楚 | [mathematical-reasoning.md](mathematical-reasoning.md) | 参数／结论能被支持到什么范围 |
| 不确定性、数值误差或统计检查不清楚 | [scientific-foundations.md](scientific-foundations.md) | 与该结论对应的检查及误差报告 |
| 多表键、实体别名、分类口径或预测信息边界不清楚 | [data-computing.md](data-computing.md) | 连接覆盖与总量对账、允许处理及实际评估身份 |
| 文件、执行、版本或证据连接不清楚 | [automation.md](automation.md) | 实际运行、有效版本与可追溯连接 |
| 结果太多，交付主线不清楚 | [convergence.md](convergence.md)、[writing.md](writing.md) | 从有效证据到报告的取舍与论证 |
| 成稿可能漏答或经不起质疑 | [review-protocol.md](review-protocol.md) | 可复现的缺口与处理决定 |
| 发生了值得迁移的成功或失败 | [learning-loop.md](learning-loop.md) | 带适用条件和证据等级的经验 |

方法选择、证据强度、失败返回与停止条件由本文件统一规定；其他参考细化所属问题，不新增全题必经步骤。

## 模型与验证一起选择

先明确预期结论，再选择能取得相应证据的模型。遇到参数区分、尺度、优化保证、概率区间或干预结论的问题，按需读 [mathematical-reasoning.md](mathematical-reasoning.md)：先判断表示与数学结构，再选择算法。常见方法的适用条件、工具与必做检查见 [model-library.md](model-library.md)。资源不能互换、需求有兼容限制时，先检查分组守恒与可达瓶颈，再用总容量；扩容改变运输／停留时间时，把在途占用和阻塞纳入比较。代理目标（容量、最大利用率）改善不自动意味着最终目标（等待、成本）改善，应以任务指标和反例核验。每个候选记录它回答哪项任务、需要什么数据、额外假设、计算代价、失效条件和独立验证办法。先做最容易推翻路线的手算或小例子；不可验证的复杂方法不能因为热门就优先。

| 任务触发条件 | 起点 | 可采用的扩展及条件 | 对应证据 |
|---|---|---|---|
| 描述或比较观测数据 | 描述统计与可解释回归 | 调整混杂或分组仅在问题与数据支持时做 | 采样、缺失、组间比较和误差检查；关联不升级为因果 |
| 需要未来数值 | 均值、持续性或季节性基线 | 回归或时序模型须改善相同验证划分下的任务表现 | 时间／组回测；开发目标与最终留出目标分离，预处理只用允许信息 |
| 解释连续变化或积累 | 平衡关系与简单动力学 | 微分方程等用于确有时间机制的任务 | 单位、守恒、边界、解析解或步长收敛 |
| 选择行动且存在硬约束 | 手工可行策略、小规模枚举 | 线性／整数规划或网络模型用于有明确目标和可行域的决策 | 约束、求解状态、上下界与最优间隙 |
| 比较多个不能仅靠硬约束区分的方案 | 先检查支配关系 | TOPSIS 仅在指标方向和偏好权重有依据时使用 | 独立已知排序、权重变化、指标重复与排名反转 |
| 参数未知可能改变结论 | 有根据的范围与情景对照 | Sobol 封装仅适合独立均匀输入与确定性标量输出 | 已知效应、样本收敛、区间与结论变化；敏感性不等于因果 |

组合模型必须有明确连接：上游输出是下游的什么输入，单位与时间尺度是否一致，误差与假设怎样传递。若不能指出连接与改善的任务，不组合。预测不自动要求优化；优化不自动要求多指标排名；所有题也不自动要求 Sobol。

路线可计算还不等于可实施。决策前逐项核对必需输入：在什么时刻、由谁、以什么精度取得，采集成本或隐私限制是否允许；未知位置、未来需求或完整系统状态不能默认为已知。依赖理想信息的结果可保留为条件解或性能界，与实际可用信息下的方案分开比较，并说明缺少观测时的替代做法。比较测量设计时，把观测成本、复位和可复用次数纳入原目标，区分指令量与实际交付量；相容模型更少不自动意味着更有用。不同观测所得的候选比较不能冒充期望信息价值，也不能据已知观测后的候选费用断言未知观测前普遍应选哪种试验；顺序试验还须核对跨试验共享偏差，不能直接把两个独立筛选集合的交集称为联合推断。各条关键假设应能指向它改变的方程、数据处理或可行域；未实际使用的背景常识不凑进假设表。这一实施性检查也回应了 [COMAP 2011 B 评述第1–3页](https://www.contest.comap.com/undergraduate/contests/mcm/contests/2011/results/2011_MCM_B_Judge_Com.pdf)对未披露输入需求和无用假设的批评，不将历史评述视为当届硬规则。

## 证据的层次

三类问题，从程序到现实逐层加深；越往下越不能靠重复运行得到。

**计算是否符合模型**
1. 代码对不对：单元测试、小例子手算、边界与奇异输入。
2. 数学计算对不对：另一种推导、解析解、穷举、不变量、约束；重复同一程序只说明运行一致。
3. 模型是否满足它应有的数学性质：守恒、单调、凸性、量纲、对偶间隙（`probe_structure`、`dimensional_analysis` 等）。

形式化证明仅在确有关键定理、环境可用且成本相称时启用，不作为每题必经步骤。审查时把“论文主张—精确数学陈述—前提—证明工件与版本—验证环境／命令—实际结果—覆盖与未覆盖范围”接起来：核对证明的是否是原主张，是否增加了决定性假设，是否依赖未证明占位或额外公理。只证明辅助引理，不能把主结论标成已证明；编译通过不证明现实假设适用，也不自动授予全局最优或获奖等级。

例如，证明目标函数 f(x)=x² 在[0,1]上凸，只支持一个性质；候选x=1的目标值1仍劣于x=0的目标值0，不能由凸性证书宣称该候选最优。把证明范围和结论分开核对，沿用现有任务ID和证据记录，不新增平行证明台账。pipeline的independent标签仍是作者声明的独立检查，不升级为形式化认证。

这一范围审查参考 [openai/math的辅助结果比较说明](https://github.com/openai/math/blob/fd4aeeb2ee4fc729c18d98444fed42fd0529eeeb/lean/ComparatorChallenges/README.md)。Praxis未安装Lean或Comparator，也未编译该仓库的证明；只吸收工件关联与验证范围的组织方法。

**模型是否回答现实问题**

4. 假设是否合理：逐条写出依据等级，并说明不成立时怎么办。
5. 数据与机制是否支持：核对目标、定义、可用信息、识别能力和替代解释。

**行动与结论是否稳健**

6. 稳健性：只扰动有现实依据且可能改变建议的因素，区分参数、输入和模型结构不确定性。
7. 独立对照能否支持同一结论：先说明它与主方法不共享的推导、实现或信息来源，再比较结果。换算法或数据切分仍可能共享模型错误；一致加强相应层面的证据，不自动确认现实机制。

**证伪**：对每个主要结论写一条证伪陈述——“看到什么结果，就说明它错了”——并做那项检查。没有任何结果能推翻的结论，等于什么都没说。

不确定性的类型、数值误差与收敛、统计检验的规范做法，见 [scientific-foundations.md](scientific-foundations.md)。根据题目结论选择检查，而不是凑固定数量。报告候选中最好、局部最优或全局最优时，证据须匹配比较范围。自动运行与 evidence 索引帮助追溯，不能替代上述判断。

## 停止深挖与交付

一次完整委托是预算内的工作 episode，可以包含多轮研究、验证和写作；不是交出初稿后等用户反复提醒，也不是后台无限运行。先接续题目、目标、允许工具、实际截止和可用预算；只有未知信息会改变关键答案或授权范围时才追问。小计算仍走直通，不因自主能力而建立整套记录。

任务定义与模型含义仍在 tasks.md；pipeline 整体哈希该文件。运行后的有效／候选指针、预算、中断点与当前一个主要行动写入 planning/progress.md（或同职责的现有非计算接续文件），引用任务和收据，不复制模型、不另列待办；实际定义／假设变化仍更新 tasks.md 并接受过期保护。按下列关系推进，失败可返回原因所在环节：

1. **形成基线与滚动完整稿。** 先回答各项要求，保存可核查的结果和当前限制。可交付说明避免完全交不出稿，不能直接当作高质量目标已达成。
2. **识别真实缺口。** 主动检查题意覆盖、定义、结构、关键假设、独立证据和全文表达。会改变主要答案或使交付无效的缺陷优先；也寻找更贴切机制、更紧的界、决策阈值或可执行策略。每个问题指向具体行动，不输出空泛“反思”。
3. **选择最有价值的下一步。** 写清对应 Q／claim、现有限制、预计改善及理由、所需数据与假设、最便宜的辨别试验、独立核验、计算＋验证＋全文同步总成本与停止条件。收益可用高／中／低并说明，不编造精确获奖增益。不为凑模型、路线或实验数量实施无价值的工作。
4. **候选上实施并核验。** 新模型、参数或表达先保留为待核验候选；检查通过且适用性明确后，才接替当前已接受成果。失败也保留原因和已花预算，不靠无限重启挑最好结果。当前输入已使旧证据过期时，旧成功不得继续冒充有效；恢复旧快照须明确决定并核对匹配输入、代码、环境与证据，执行限制见 [automation.md](automation.md)。
5. **同步受影响内容并重新判断。** 根因修复和增量检查按下节执行；更新相关主张、图表、正文、摘要、结论及非技术说明。完成后检查真实缺口是否解决、候选是否改善答案，再选择下一行动；没有适用机会不强制造一次升级。

预算分别记实际历时、计算资源、可获取的模型用量和真实人工介入；未知不估造，不用文件时间代替工作时间。行动前保护独立验证、终稿审读、渲染与交付余量；工具超时、权限或宿主限制时保存中断点、有效／候选版本、失败、剩余缺口与下一步。接续先核对真实文件和日志，不重复长计算，不把中断步骤当完成。宿主不能继续运行时明确停止，不声称后台仍在研究。

**停止判断分开回答“能否交付”和“是否值得继续”。** 请求范围已满足、证据与强度匹配、关键矛盾已处理或明确保留为限制，且继续改进的预期收益低于成本，才结束质量循环；预算只够验证与交付时停止扩展。预算尚足且存在可修复的重要缺口时继续，不用降低措辞强度逃避修复。无法解决的问题保留未完成或条件结论，时间到不是检查通过。完整报告的证据取舍见 [convergence.md](convergence.md)，单人限时优先级见 [solo-delivery.md](solo-delivery.md)。

上述质量判断由宿主中执行者承担；[workflow.md](workflow.md) 的可选协调入口只执行经验检索、状态连接、预算与证据门禁，不提供后台研究服务。文档、模板或脚本结构通过不证明自主能力；须保存真实任务中首次委托后的主动改进、候选失败与中断接续证据，检查覆盖范围分别报告。

## 根因修复与全文变更影响

复用现有 Q、claim、run、issue 与文件位置，为主要主张连接：原题要求 → 定义／条件 → 模型／数据 → 运行／证明 → 主张 → 表图／正文／摘要／结论。已有数值索引用 requirements.json，含义与非数值关系放任务记录；不为每句话建对象，不另建平行问题系统。

重要评语先定位并复现。共享原因的症状共用 issue ID，区分怀疑与已确认根因；相似文字不足以证明同因。按“复现 → 根因 → 实际下游 → 源头修复 → 必要重算／重检 → 全文同步 → 直接回归”处理。错误评语可有据反驳，角色一致不自动成为独立证据。严重格式违规也可能使交付无效，按影响而非问题名称排序。

首次接手整稿、改主线或关键假设／模型／结论前，读当前全文、题目和必要图表证据。之后局部修改可沿用已建立的全局理解，先核对版本并读受影响上下文；重大变更重建全局理解。最终交付读最终成稿并看渲染页面，编译成功不代表版面验收。

| 实际改动 | 必要核查与同步 |
|---|---|
| 拼写、标点、局部自然度 | 本段及上下文含义；版面变化时编译查看，不重跑模型 |
| 章节、段落或图表组织 | 全文主线、交叉引用与任务覆盖，渲染受影响页面 |
| 数据、参数、模型方程 | 重算实际下游，更新对应检查、主张及所有表达位置 |
| 新增验证条件 | 现有轨迹足够则重放检查，不足才追加计算，不默认重做优化 |
| 证明或数学前提 | 复核证明范围及所有依赖结论，不因代码未变跳过 |
| 纯贡献追加 | 更新真实归属，按 [contributions.md](contributions.md) 处理，不使数值过期 |
| 依赖未知 | 说明原因并保守扩大核查／重算，不静默复用 |

复用须有匹配的输入、代码、参数、环境和检查范围。关键结果尽量从同一运行数据生成表格、摘要数字、推荐、比较与图注，减少手工双份维护；生成只能防部分数字漂移，条件、单位、比较对象与结论强度仍需审读。最终全稿验收与计算重跑范围分别判断。

## 失败回到原因所在的环节

| 发现的问题 | 返回哪里 | 下一步 |
|---|---|---|
| 对象、分母、量词或目标被误读 | 明确问题 | 用区分例子修正定义，并更新受影响任务 |
| 数据无法识别参数或支持目标结论 | 形成路线 | 调整模型或降为有边界的情景分析；确需输入时询问 |
| 公式实现、数据处理、约束或求解失败 | 取得结果 | 修复实现并回归直接依赖；不以改写假设掩盖错误 |
| 程序正确但机制不适用或不胜基线 | 形成路线 | 修改模型或保留基线，不重复运行冒充新证据 |
| 建议随合理假设变化 | 判断证据 | 说明变化阈值与适用条件，必要时给条件建议 |
| 证据版本过期或报告数字不一致 | 取得结果／完成回答 | 重算受影响结果并同步交付物 |

问题修复且相关检查通过就向前推进；没有新矛盾不重复同样检查。关键问题未解决时保留失败状态，不能仅因预设轮次结束就判定通过。

## 组合示例：需求预测服务于资源分配

用户若只问明年的需求，任务是预测，比较基线并验证误差即可。若还问有限预算下如何分配资源，则有预测和决策两项任务：预测输出进入分配模型，明确需求单位、期间、成本与容量约束；预测误差用有依据的情景传到决策中。只有实际存在多种利益取舍时才引入多目标或评价；只有不确定参数值得全局分解且满足输入条件时才用 Sobol。

这一例子说明方法之间的调用关系，不是假定每题都需要这一组工具，也不提供未经实际数据计算的结果。

## 吸收外部方法的统一规则

引入前明确：当前哪项任务或已观察失败需要它、它承担主线中的哪种职责、输入条件与输出契约、它替代／补充现有哪一处、怎样验证改善，以及许可是否支持实际复用。职责重复就合并；条件冲突就保留条件分支；收益不足就不引入。

实际问题形成可公开的小例子后再补回归检查，同时修改对应环节的指导或工具。不要每发现一个项目就新增一个阶段或永久检查项。

## 按上述条件调用的工具

### 全局敏感性

```python
from modeling.sensitivity import sobol_sensitivity

result = sobol_sensitivity(
    model=lambda x: 2*x[:, 0] + x[:, 1],
    names=['a', 'b', 'unused'],
    bounds=[[0, 1], [0, 1], [0, 1]],
    n=2048, seed=2027,
)
```

当前封装限定独立、连续、均匀输入与确定性标量输出。`n` 必须为至少 64 的 2 的幂；默认计算预算 100,000 次，实际调用数为 `n*(参数数+2)`。保留主效应 S1、总效应 ST 与 95% bootstrap 区间半宽，不输出成对二阶估计。模型返回值必须与采样行逐一对应；不能把任意现成 Monte Carlo 样本塞进去。发现常量、非有限输出或预算超限时拒绝分析。不随意截断负的数值估计；加大样本量检查收敛。采样分布和独立性没有现实依据时，只能将其解释为假设情景。

### 方案评价与权重稳定性

```python
from modeling.decision import evaluate_alternatives

result = evaluate_alternatives(
    matrix=[[3, 1, 7], [2, 2, 7], [1, 3, 7]],
    weights=[0.4, 0.4, 0.2],
    directions=[-1, 1, 1],  # 成本越小越好，收益越大越好
    alternatives=['A', 'B', 'C'],
    criteria=['cost', 'benefit', 'constant'],
    trials=1000, weight_sigma=0.35, seed=2027,
)
```

采用明确的 min-max 标准化。常量和零权重指标会被剔除并报告，剩余权重重新归一化；全无区分度时不编造排名。权重通过乘法对数正态扰动产生情景；并列第一平分情景份额。份额是该扰动设定下的结果，不能叫客观获胜概率。默认扰动幅度只是可修改的演练设定；真实应用需说明偏好范围，并额外检查指标重复、方案集合变化与标准化造成的排名反转。
