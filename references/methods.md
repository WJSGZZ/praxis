# 建模主线

用Q/claim ID逐问连接原文要求、定义与条件、模型、有效输出、独立证据和正文直接答案，沿用tasks/progress唯一记录。先核对象、分母、单位、量词、信息时点和主要歧义；合理替代解释保留条件答案，未知不阻塞独立部分。

标准题比较同目标、期限、输入与可用信息的基线和一条实质备选；陌生或影响大的问题至少三条结构不同路线，先廉价反驳再选。仅一条自然方法的局部题给理由与独立核查。关键偏好与用户确认。代理指标改善回到原题指标；预测、证明、优化各按主张所需证据判断，运行成功不证明适用性。

区分事实、定义、比较约定、实质假设与参数情景。前提给理由、所改方程/可行域、实际用途、失效影响及检验。参数给值/范围、单位、条件与具体来源；未知值标情景，不能编造。核量纲/尺度、分组守恒、边界、极限、依赖与可辨识性；组合模型传播上游条件和误差。自选强条件无解仅排除该条件。

分别核实现符合公式、数学结论成立、现实适用和建议可执行。独立检查须有不共享的推导、实现或信息，明确仍共享前提；每个主要答案给可证伪检查并执行。按有据范围检验会改变答案的参数、结构、信息及执行偏差，给阈值与条件动作；量词、外推、最优/因果/泛化范围不得超证据。

先形成各问基线与滚动完整稿，预留独立核验、阅读和交付。改进先写预期收益、廉价辨别试验、计算+验证+全文同步成本和停止条件；失败保留，通过科学检查才替换有效版本。有重要可修缺口且预算足够就继续；满足请求、证据相称且边际收益不足成本时停，缺口与恢复条件沿唯一记录交接。

重要问题按复现→共同根因→实际下游→源头修复→必要重算/重检→全文同步→直接回归处理。改主线或关键前提前读原题和全文；局部语言复用未变数值，数据/方程/证明变更追实际依赖，未知依赖扩大检查。终稿审读与计算重跑范围分别判断。

# Praxis 的统一建模方法

围绕原始问题形成答案，让结论的强度、条件与实际证据相称。

## 工作单元与记录

工作单元是需要回答的问题，用 Q1、Q2 等 ID。先从原文列要求，再定义、选路线、实现、验证和表达。持续任务沿用已有记录；案例的 `planning/tasks.md` 维护含义、取舍、假设与依赖，`planning/requirements.json` 用相同 ID 作机器索引。成熟小问题直接回答，沿用已有记录。

先解决影响其他答案的定义与数据，按依赖推进；局部未知时继续独立部分。跨案例依赖在 tasks.md 显式标注，传播范围由执行者核对。实际原文条目与算前声明分别按 [论文清单](contest-paper-checklist.md)、[建模门禁](modeling-gate.md) 产出。

## 一条主线，按请求范围进入和结束

| 环节 | 要回答的问题 | 产出与推进条件 |
|---|---|---|
| 明确问题 | 什么才回答了原题？ | 原文要求、目标量、单位、约束、信息与交付物；处理主要歧义或给条件分析 |
| 形成路线 | 哪种结构与最小模型能回答？ | 基线、实质备选、假设、淘汰依据和独立验证设计；复杂度对应实际缺口 |
| 取得结果 | 怎样可靠计算？ | 审核模型、数据和验证器，保留真实运行、输出与失败 |
| 判断证据 | 支持多强的结论？ | 独立答案、数学性质、现实适用性和稳健性；缺证则修复或限定 |
| 完成回答 | 怎样交付原题要求？ | 条件答案、来源、图表／报告与未决项逐问对应，实际成品通过审阅 |

这些是推理依赖，可从请求对应环节进入。**路线数量**唯一在此规定：标准题比较基线加一条实质备选，记取舍与检查；陌生题或结论影响大时比较至少三条结构不同的路线，按 [结构发现](structure-discovery.md) 和 [路径搜索](path-search.md) 廉价探索、攻击、淘汰及重组。只有一条自然方法的局部小题直接给理由与独立核查。无标准答案时按 [研究模式](research-mode.md)；结束时从真实成功和失败提炼 [经验](learning-loop.md)。

## 按缺口读取，规则各有归属

| 缺口 | 唯一首读与产出 |
|---|---|
| 专业职责不清 | [capabilities.md](capabilities.md)：主责与交接 |
| 结构或候选不清 | [structure-discovery.md](structure-discovery.md)：结构、候选与取舍 |
| 表示／识别／保证不清 | [mathematical-reasoning.md](mathematical-reasoning.md)：可支持范围 |
| 误差／统计／不确定性 | [scientific-foundations.md](scientific-foundations.md)：相称检查 |
| 数据连接与信息版本 | [data-computing.md](data-computing.md)：口径、覆盖与对账 |
| 执行与证据身份 | [automation.md](automation.md)：有效运行与连接 |
| 组稿／成品 | [writing.md](writing.md)：主线与实际页面；发现缺口再按 [review-protocol.md](review-protocol.md) 复核 |

## 模型与验证一起选择

先确定目标结论及所需证据，查 [model-library.md](model-library.md) 对应方法。每个候选记录任务、额外前提、数据、成本、失效条件与独立验证，先做最便宜的反驳。

| 任务 | 基线／升级条件 | 核查 |
|---|---|---|
| 描述观测 | 描述统计、可解释回归；按采样设计扩展 | 缺失、依赖、分母与误差；因果另核识别 |
| 预测未来 | 持续性／季节朴素；相同留出上改善才升级 | 信息时点、滚动起点、目标与损失一致 |
| 连续积累 | 平衡与简单动力学；时间机制支持时加方程 | 单位、守恒、边界与解析／收敛对照 |
| 行动有硬约束 | 手工可行策略／枚举；结构适用再求解 | 可行性、界、间隙及执行所需信息 |
| 多方案取舍 | 支配关系；有偏好依据再加权评价 | 指标重复、权重变化和排名反转 |
| 未知量影响结论 | 有依据范围与情景；分布适用再传播 | 依赖、联合输出、阈值与建议变化 |

组合模型注明上游输出、下游输入、单位、尺度、误差与条件传递。逐项核输入何时由谁以何精度取得及成本；理想信息下的界与可实施策略分别报告。量级与多对象服务先核分组平衡和可达瓶颈，再汇总；代理目标的改善回到原题指标验证。算法使用范围由专业参考细化。

## 假设、理由与结论范围

假设合理性的唯一方法规则在此；竞赛的章目与表格格式按 [论文清单](contest-paper-checklist.md)。

- 区分题面事实、变量定义、比较约定、模型假设与参数情景，逐方程查实际使用的隐含前提。
- 每项实质前提给观测／文献理由或简化目的，指向所改方程、数据处理或可行域；核对题面、数据和待证目标，保留有实际用途的前提。
- 对影响主答案的参数、结构和信息条件，用解析特例、边界、替代机制或观测作相称检验；分别报告模型内计算正确性和现实适用性。
- 缺证时写清条件、影响及恢复所需观测；摘要、数值、建议和量词沿用同一范围。自选更强条件的无解只排除该条件，原题的其他解释继续回应。

依据为 [COMAP 参赛说明](https://contest.comap.org/undergraduate/contests/mcm/instructions.php)、[参赛指南](https://contest.comap.org/undergraduate/contests/mcm/flyer/MCM-ICM_Tips.pdf)与[历年评委经验](https://www.contest.comap.com/undergraduate/contests/resources/PDF/20YearsofGoodAdvice.pdf)；章目默认与官方要求分别记录。

## 证据的层次

| 层次 | 应取得的证据 |
|---|---|
| 实现符合公式 | 独立手算、小例、边界与异常输入；正文公式、实现和输出分别核对 |
| 数学结论成立 | 解析解、穷举、守恒／不变量、界或另一推导；写前提、范围与误差 |
| 模型回答现实 | 目标、定义、数据、机制、识别与替代解释；说明假设失效影响 |
| 建议可用 | 与同信息基线比较，检验关键未知与执行偏差，给建议变化阈值 |

独立对照注明与主方法不共享的推导、实现或信息来源，以及仍共享的前提。形式证明按原任务连接“主张—精确陈述—前提—工件版本—验证环境与结果—覆盖范围”；证明辅助性质时仅赋予该性质的结论。每个主要答案写出可推翻它的观察或检查，并实际执行。敏感性步骤唯一归 [论文清单](contest-paper-checklist.md)，数值与统计细节归 [scientific-foundations.md](scientific-foundations.md)。

## 停止深挖与交付

1. 接续目标、允许输入、截止与可用预算，预留独立核验、终稿审读、渲染和交付余量。
2. 先形成各问基线与滚动完整稿；按 Q／claim 识别影响主答案的真实缺口。
3. 下一动作写预期改善、条件、最便宜辨别试验、计算＋验证＋全文同步总成本及停止条件，再在候选上实施。
4. 通过科学检查且适用性明确后接替当前成果；输入改变时按快照重核有效性，失败保留。
5. 请求满足、证据相称、主要矛盾处理且继续收益低于成本时结束；预算不足时保存条件结论与具体缺口。
6. 有可修复重要缺口且预算足够则继续；中断时写实际历时、可取得用量、候选／有效版本、恢复条件和下一动作，未知标未知。
7. 定义仍归 tasks.md，实际预算、当前指针与中断点归 planning/progress.md；沿用唯一记录。
8. [workflow.md](workflow.md) 连接状态和门禁；自主能力由真实任务证据检验。

## 根因修复与全文变更影响

复用 Q、claim、run、issue 与文件位置，连接“原题要求 → 定义／条件 → 模型／数据 → 运行／证明 → 主张 → 表图／正文／摘要／结论”。数值索引用 requirements.json，含义与非数值关系写原任务记录。

重要评语先定位并复现，共享原因的症状共用 issue ID；分别标怀疑、确认和实际影响。按“复现 → 根因 → 实际下游 → 源头修复 → 必要重算／重检 → 全文同步 → 直接回归”处理，以证据核实评语和角色独立性，按影响排序。

首次接手整稿、改主线或关键假设／模型／结论前，读当前全文、原题和必要图表。局部修改先核版本与受影响上下文，重大变更重建全局理解。最终交付读最终成稿并查看渲染页面，编译诊断与视觉审阅分别记录。

| 实际改动 | 必要核查与同步 |
|---|---|
| 拼写／局部语言 | 核本段与上下文，查看受影响版面，复用未变数值 |
| 组织／章节／图表 | 核全文主线、交叉引用、任务覆盖及对应页面 |
| 数据／参数／方程 | 重算实际下游，同步检查、主张及各表达位置 |
| 新验证条件 | 轨迹足够则重放检查，不足再追加计算 |
| 证明／数学前提 | 核证明范围及全部依赖结论 |
| 纯贡献追加 | 按 [contributions.md](contributions.md) 更新真实归属，数值有效性按实际输入判断 |
| 依赖未知 | 写明原因并扩大检查范围 |

复用需输入、代码、参数、环境和检查范围匹配；尽量由同次运行生成图表、摘要数字与推荐，再人工核条件、单位、对象和结论强度。最终全稿审阅与计算重跑范围分别判断。

## 失败回到原因所在的环节

| 发现的问题 | 返回哪里与动作 |
|---|---|
| 对象／分母／量词／目标误读 | 明确问题：用区分例子修定义与关联任务 |
| 数据不足以识别 | 形成路线：换模型或有边界情景，列恢复输入 |
| 实现／处理／约束失败 | 取得结果：修实现并回归直接依赖 |
| 机制不适用或不胜基线 | 形成路线：改模型或保留基线，记录失败 |
| 合理前提改变建议 | 判断证据：给阈值、范围与条件动作 |
| 版本过期／表达不一致 | 取得结果／完成回答：重核下游并同步 |

相关检查通过就向前，按新信息决定追加检查；未解决关键缺口保留失败与恢复动作。

## 吸收外部方法的统一规则

引入前明确当前任务或已观察失败、它承担的职责、输入条件与输出契约、替代／补充位置、验证改善的方法及许可。职责重复就合并，条件冲突就保留分支，收益不足就沿用现有方法。

将真实问题形成可公开小例后补回归，同时更新所属指导或工具；新增永久步骤须有实际重复需求。案例专有教训留用户经验库，通用算法的调用细节归 [model-library.md](model-library.md)。
