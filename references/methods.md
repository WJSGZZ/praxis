# 问题分析与模型选择

按实际任务选择模型；这不是任何赛事的评分标准，也不是按题号套模型的清单。

## 1. 先定义要交付什么

读题后先填写 `references/tasks-template.md` 的实际副本，把每个要求写成可回答的问题。至少明确：谁用这个结果、要做什么决定、输出是什么、允许使用什么数据、时间和资源边界在哪里。把题目要求与自己提出的扩展分开，先完成要求。

例如，“找到最佳方案”需要先明确方案集合、约束、评价目标和利益相关方；“预测未来”需要明确预测对象、时间跨度、可用的历史信息与误差指标。不能因为题目出现“影响”就自动把相关性分析写成因果结论。

## 2. 把已知、假设和未知分开

事实和参数注明原始来源。每个重要前提标记为：已证实、有证据待确认、目前无证据、不可能或极不可能；后者必须说明依据。自己的建模假设单列，不能改写成已证实事实。

对每个假设写清三件事：为什么现在采用、哪种现象会推翻它、被推翻后结论是否改变。优先核验能改变模型路线的未知，不无限搜集背景材料。数据不足时可以做有明确边界的情景分析，不能虚构观测数据。

## 3. 先画机制，再选数学形式

写出变量、单位、时间尺度、因果方向和约束。明确系统边界：哪些机制在模型内，哪些作为外部输入，哪些暂不考虑。对输入到输出之间的每一步问：依据是什么，能否测量，能否独立检查？

| 实际任务 | 优先考虑的简单基线 | 验证重点 | 当前工具 |
|---|---|---|---|
| 描述数据、比较群体 | 描述统计、可解释回归 | 采样偏差、组间差异、缺失与混杂 | pandas、statsmodels |
| 预测数值或时间序列 | 均值／持续性／季节性基线，再比较回归或时序模型 | 留出或滚动回测；只使用当时可获得的信息 | scikit-learn、statsmodels |
| 连续变化、积累或守恒 | 平衡关系、微分方程 | 单位、守恒、边界、解析解、步长 | SciPy、SymPy |
| 资源分配、调度、路径 | 规则策略、小规模枚举、线性／整数规划 | 可行性、上下界、求解状态、最优间隙 | SciPy/HiGHS、NetworkX |
| 比较多个方案 | 先检查支配关系与硬约束，再使用透明的多指标评价 | 指标重复、偏好依据、权重变化与排名反转 | pyMCDM，本地 decision 封装 |
| 参数不确定且可能相互作用 | 单参数扰动作为初筛，再做全局敏感性 | 分布依据、相关性、交互、样本收敛 | SALib，本地 sensitivity 封装 |
| 政策／可持续性建议 | 可计算的成本收益、情景与约束模型 | 谁受益或承担成本、适用范围和不同情景 | 按机制组合以上工具 |

这是候选起点，不是固定答案。复杂模型必须解释它修复了基线的什么缺陷，且有验证收益。数据拟合得好不能自动证明机制正确。

## 4. 先做小型“会失败的检查”

在完整实现前，用极端情况、手算小例子或样本检查路线。至少想出一个不符合预期时必须重新考虑模型的结果。

- 守恒模型：输入为零、时间很短或很长时是否合理？
- 预测模型：是否胜过朴素基线，还是仅在训练集好看？
- 优化模型：手工可行方案能否被找到，约束是否真的限制了解？
- 评价模型：全面更好的方案是否更好；换权重会不会换赢家？
- 敏感性模型：完全无关的输入是否接近零；已知交互能否被识别？

先失败的小例子，比写完论文后才发现错更有价值。如果路线失败，记录原因并退回基线或改机制，不把失败藏进假设。

## 5. 比较候选模型的收益和代价

每个候选方案列出：需要的数据、要新增的假设、实现与计算成本、可解释性、验证能力、失效条件。只有当新增复杂度改善关键任务并能验证时才保留。

优先选“能完成并有证据的方案”，不按热门算法、仓库星数或论文奖项标签决定。对小数据，不把神经网络默认当作进步；对决策，不把熵权法生成的权重默认当作人的偏好；对因果问题，不把预测重要性默认当作干预效果。

## 6. 把三个检查分别做完

**实现是否正确**：手算、解析解、穷举、单位、边界、约束、数据顺序、可复现运行。

**模型是否适合现实**：机制是否成立，数据能否识别参数，误差是否随情景系统性变化，是否存在替代解释。

**决策是否稳健**：更换合理参数、数据处理、权重或模型后，建议是否改变；改变发生在什么范围。把敏感性、输入不确定性和模型结构不确定性分开。

自动测试主要帮助第一项，不能替人完成后两项。

## 7. 结果怎样进入论文

每个重要结论都回指计算结果、图表和来源，正文里的数字不能凭记忆填写。论证顺序是：问题与选择 → 假设和依据 → 模型 → 求解与结果 → 独立核验 → 局限 → 建议。

摘要最后写：说清使用了什么、得到什么具体结果、如何验证、结论适用于哪里。正文、图表、摘要与指定 memo/letter 必须一致。工具的许可证与代码来源记录用于保留复用依据，论文仍要在使用处正确引用工具和方法；开源工具不能证明自己的模型正确。

## 当前可调用的两个新增工具

### 全局敏感性

```python
from modeling.sensitivity import sobol_sensitivity

result = sobol_sensitivity(
    model=lambda x: 2*x[:, 0] + x[:, 1],
    names=['a', 'b', 'unused'],
    bounds=[[0, 1], [0, 1], [0, 1]],
    n=2048, seed=2027,
)
```

当前封装限定独立、连续、均匀输入与确定性标量输出。`n` 必须为至少 64 的 2 的幂；默认计算预算 100,000 次，实际调用数为 `n*(参数数+2)`。保留主效应 S1、总效应 ST 与 95% bootstrap 区间半宽，不输出成对二阶估计。模型返回值必须与采样行逐一对应；不能把任意现成 Monte Carlo 样本塞进去。发现常量、非有限输出或预算超限时拒绝分析。不随意截断负的数值估计；加大样本量检查收敛。采样分布和独立性没有现实依据时，只能将其解释为假设情景。

### 方案评价与权重稳定性

```python
from modeling.decision import evaluate_alternatives

result = evaluate_alternatives(
    matrix=[[3, 1, 7], [2, 2, 7], [1, 3, 7]],
    weights=[0.4, 0.4, 0.2],
    directions=[-1, 1, 1],  # 成本越小越好，收益越大越好
    alternatives=['A', 'B', 'C'],
    criteria=['cost', 'benefit', 'constant'],
    trials=1000, weight_sigma=0.35, seed=2027,
)
```

采用明确的 min-max 标准化。常量和零权重指标会被剔除并报告，剩余权重重新归一化；全无区分度时不编造排名。权重通过乘法对数正态扰动产生情景；并列第一平分情景份额。份额是该扰动设定下的结果，不能叫客观获胜概率。默认扰动幅度只是可修改的演练设定；真实应用需说明偏好范围，并额外检查指标重复、方案集合变化与标准化造成的排名反转。

运行已核验的合成示例：

```bash
uv run --locked python -m examples.decision_sensitivity_demo
```
