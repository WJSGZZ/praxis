# 论文评审协议：先找出能被攻击的地方，再交稿

完整稿交付前，或重要结论仍有风险时，用下表选择与风险相关的审查视角；局部改稿直接检查受影响部分，不固定跑完全部角色。每次先读成稿、原题和必要证据，把发现写成清单，再核对作者的解释，避免先被辩护带偏。

同一助手可切换视角；用户或当前协作规则允许代理分工时，也可分配适合独立审读的部分。不同角色或不同代理都不自动产生独立证据，仍按 [methods.md](methods.md) 判断检查与主方法共享了什么前提。

| 角色 | 只问什么 | 典型发现 |
|---|---|---|
| 数学评审 | 公式、推导、单位、边界、数值收敛、约束是否真的满足 | 约束被取样间隔绕过；受约束的量随网格不收敛；证明漏条件 |
| 建模评审 | 假设与现实是否吻合；模型是否比必要的更复杂；是否与数据矛盾 | 边界条件被数据否定却自称已验证；替代结构没有真正被试过 |
| 数据与来源评审 | 数据来源、清洗、参数出处、有无泄漏、引用是否真实 | 参数没有出处；留出集参与了调参 |
| 评分评审 | 对照题面逐问核对：每问是否答全、是否回答了被问的问题、有无评分点遗漏 | 漏答子问；把“求最优”答成“给出一个可行解”；规则中的数字或倍率读错（对照题面渲染页）；写了“已核对”却没有核对记录 |
| 语言评审（每种语言单独读成稿） | 翻译腔、套话、防御性免责与重复辩解、术语不统一、主语与时态混乱、摘要是否先给结论和数字 | “Aiming at … we …”式的中式英语；“具有较强的鲁棒性”式的空话；同一量在两节用两个名字 |
| 反方 | “证明这篇论文不该得高分，最容易击破哪里？” | 摘要数字与正文不一致；最大风险假设没有量化 |

## 做法

1. 每个角色输出：问题、位置、严重度（会改变结论／影响可信度／仅表述）、建议。
2. 作者逐条处理：改正、反驳（要有证据）、或在论文中如实写入限制。不采纳也要记原因。
3. 修改模型、数据或参数后，重算受影响的数字及其下游，核对对应摘要、正文、表与附录；只有表述改变时不重复计算。
4. 发现与处理决定写回已有任务记录；需要完整评审清单时留在案例 planning 目录并链接原任务。论文展示实际论证与结果，不用评审轮次证明质量。

## 已知的盲区

- 评审可能共享模型与信息盲点；重要结论需可复算的独立对照，仅另写一份同公式程序也不能排除共同的建模错误。
- 评审提出的“问题”也可能是错的：对每条发现先复现，再改。
- 没有校准的评分至多作为探索性比较，不能声称绝对分数或稳定排序。需要能力评价时按 [../evals/PROTOCOL.md](../evals/PROTOCOL.md) 做盲评、重复与校准；评审本身不能代替模型验证。
