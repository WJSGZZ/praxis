# 论文评审协议：先找出能被攻击的地方，再交稿

完整稿交付前，或重要结论仍有风险时，用下表选择与风险相关的审查视角；局部改稿按影响选择审查视角，不固定跑完全部角色；全文理解、根因关联和变更影响统一按 [methods.md](methods.md)：首次接手和重大变更建立全局理解，后续局部编辑先核对版本与受影响上下文；修复可以局部，最终交付验收覆盖全稿。每次先读成稿、原题和必要证据，把发现写成清单，再核对作者的解释，避免先被辩护带偏。

同一助手可切换视角；用户或当前协作规则允许代理分工时，也可分配适合独立审读的部分。不同角色或不同代理都不自动产生独立证据，仍按 [methods.md](methods.md) 判断检查与主方法共享了什么前提。

| 角色 | 只问什么 | 典型发现 |
|---|---|---|
| 数学评审 | 公式、推导、单位、边界、数值收敛、约束；有证明工件时按methods.md核对陈述对应与覆盖范围 | 约束被取样间隔绕过；辅助引理被冒称主定理；证明增加决定性条件 |
| 建模评审 | 实际及隐含假设的用途、理由、现实依据与影响，按methods.md核查；复杂度是否有用；是否与数据矛盾 | 假设多／少被误当质量判据；把核心问题假设掉；边界条件被数据否定却自称已验证；替代结构没有真正被试过 |
| 数据与来源评审 | 数据来源、清洗、参数出处、有无泄漏、引用是否真实 | 参数没有出处；留出集参与了调参 |
| 题意／研究目标评审（按用途） | 竞赛对照题面逐问核覆盖；研究核主结果、文献定位与研究目标；只用当前用途的标准，不将研究生竞赛当原创研究 | 漏答子问；把“求最优”答成“给出一个可行解”；规则中的数字或倍率读错（对照题面渲染页）；写了“已核对”却没有核对记录 |
| 语言评审（每种语言单独读成稿） | 翻译腔、套话、防御性免责与重复辩解、术语不统一、主语与时态混乱、摘要是否先给结论和数字 | “Aiming at … we …”式的中式英语；“具有较强的鲁棒性”式的空话；同一量在两节用两个名字 |
| 反方（按用途） | 竞赛问“主要答案和质量判断最容易击破哪里”；研究问“核心命题、贡献与重要性最容易击破哪里” | 摘要数字与正文不一致；最大风险假设没有量化 |

## 做法

1. 每个角色输出：问题、位置、严重度（会改变结论／影响可信度／仅表述）、建议。严重度先核实际影响，不把已识别的时点、单位、定义或阈值疑点直接叫“可选澄清”：从原题和当前稿抽取实际主张及判定式，将原解释与修正解释在相同允许信息、参数及单位下并列；用相称的独立推导、精确小例或边界重放检查是否改变接受／拒绝、推荐、可行性或最优性。反例也须核输入合法性、方向、等号和量词，不用额外条件或不可得真值制造翻转。已有翻转见证的相关操作规则须修；影响不足标待核，不能默认无害。少量没有翻转的样本不证明全域无影响；仅表述的判断需有相称的等价性或稳定界依据。已确认的事实错误仍须修，即使某个给定建议未翻转。拼写及纯风格修改不强制数学实验。
   用同一 issue ID 沿定义／公式、计算或操作规则、图表、正文与摘要／结论追踪真实依赖。操作阈值错误不自动否定未受影响的冻结数值；数值字节未变也不能豁免错误操作规则。先给实际影响证据，再安排修改优先级，不按措辞轻重或角色票数裁决。
2. 作者逐条处理：先复现重要批评，区分怀疑与已确认根因，复用 issue ID 连接受影响 claim／run／文件。重要批评对应一个能区分成立与不成立的检查，先给检查条件、预算和判据，再连接实际结果与处理决定（改模型、缩窄论断、有据反驳或待核）；换一段回应不是新证据。声称组件带来收益时，按实际风险做删除／替换或同信息同预算对照，不能只重放己方方案；纯证明与标准小题不强制消融。失败候选保留，验证合格才替换有效稿。修源头后同步症状，不重复计同一根因；错误批评有据反驳，未决问题保留。不采纳也记原因。
3. 先按数据、模型、代码、依赖与验证条件的变化确定哪些证据过期；未变且哈希可追溯的计算继续复用。修改模型、数据或参数后，只重算受影响的数字及其下游；新增结构对照优先重放已有方案，不默认重做全部优化。只有表述改变时不重复计算。
4. 完稿后通读摘要、题意覆盖、假设、符号、公式、图表、结论、使用者说明及附录，核对数值、条件与结论强度一致；局部措辞变化也可能改变上下文。重新编译与逐页看PDF属于文稿验收，不等于重跑模型。
5. 发现与处理决定写回已有任务记录；需要完整评审清单时留在案例 planning 目录并链接原任务。论文展示实际论证与结果，不用评审轮次证明质量。

## 作品质量的结论

完整作品交 [praxis-review](../skills/praxis-review/SKILL.md) 分类评价。局部数学核验交 verify，写作与页面审读交 report；每个视角只在相应主张存在时使用，不固定跑完全部角色。完整竞赛稿按 [评测约定](../evals/judging.md) 报所属赛事的奖项参考档次、依据、主要差距与修改；研究稿用同一入口的定性研究评议，重点核查相对已有工作的原创增量与数学价值。两者都绑定实际稿件版本与检查范围；局部数学检查不伪装成整稿评审。

## 已知的盲区

- 评审可能共享模型与信息盲点；重要结论需可复算的独立对照，仅另写一份同公式程序也不能排除共同的建模错误。
- 评审提出的“问题”也可能是错的：对每条发现先复现，再改。
- 没有校准的评分至多作为探索性比较，不能声称绝对分数或稳定排序。需要能力评价时按 [../evals/PROTOCOL.md](../evals/PROTOCOL.md) 做盲评、重复与校准；评审本身不能代替模型验证。
