# 数据与计算能力

当任务进入实现、复算或数据质量问题时使用。任务含义与验证设计由 methods.md 提供；文件接收与运行命令见 automation.md，不另设推进流程。

## 输入到输出的契约

从原始输入用代码生成处理数据，记录单位、键、时间索引与缺失处理。模型读取什么、输出什么、顺序如何对应，都应可核对。更改编码、单位、聚合或缺失策略会改变答案时，在任务记录解释原因及影响，不把处理当无关机械步骤。

训练中学到的标准化、填补、特征选择等只对训练数据 fit；验证数据使用已学变换。交叉验证中，每个划分的变换也需重新在相应训练折拟合；时间和组边界由实际问题定义。可使用已有 scikit-learn Pipeline 将步骤结合，但 Pipeline 本身不保证划分、特征时点或调参没有泄漏。[scikit-learn 常见问题](https://scikit-learn.org/stable/common_pitfalls.html)

## 数值计算与失败

记录随机种子与实际环境。根据结构选择已有求解器，检查状态、可行性、容差与非有限值；改变初始点或精度不应被当成改变问题定义。连续模型看步长／收敛，离散模型保留整数约束，精确小例子可用 SymPy 对照数值结果。

把长期复用的处理与模型写成可审查源码，探索结果只有在同样输入下可重现后才进入正式输出。验收关注原题对应、信息边界、已知答案或独立约束，不只检查文件生成。

输出交给验证的是实际模型、处理说明、有效运行和结果；交给图表／写作的是经过检查的数值与限制，不是截屏或手抄数字。


连续过程的约束若要求全时间成立，离散采样通过不能自动证明采样点之间也可行。根据动力学选择事件检测、保守导数包络或更严格的数值认证；说明前提与求解误差余量。对分段控制在切换点分开处理，不跨越跳变插值。解析极限、独立积分器与守恒检查承担不同职责，不能把同一物理系数的两个积分器称为两套独立物理模型。
